# GDD-08.13 - Подземелья, рейды и PvE-испытания

**ЧЕРНОВИК НА СОГЛАСОВАНИЕ 23.11.2026.** GDD-08.12 утверждён. Только проектирование, без внедрения.

## Цель
Повторяемый групповой PvE-контент на базе пятичленных групп (PARTY-SIZE-087 B), ролей, персонального лута и боссов. Не превращать обязательную сюжетную линию в принудительную групповую игру.

## Варианты для утверждения
- **DUNGEON-0813:** A только сюжетные одноразовые подземелья; **B сюжетные и повторяемые подземелья** (рекомендация); C только процедурные бесконечные этажи.
- **PARTY-0813:** A только соло; **B соло-режим для части подземелий + группы до 5 для сложных** (рекомендация); C все подземелья строго на 5 игроков.
- **DIFFICULTY-0813:** A один уровень сложности; **B обычный, героический и испытание с понятными модификаторами** (рекомендация); C динамическая бесконечная сложность.
- **RAID-0813:** A без рейдов; **B отдельные рейдовые боссы на 2 группы по 5 игроков** (рекомендация); C массовые рейды на 30+ игроков.
- **LOCKOUT-0813:** A неограниченные ценные награды; **B повторяемое прохождение и персональные лимиты ценных наград** (рекомендация, согласовать с RESPAWN-086 B); C одно прохождение в неделю.

## Архитектура и UX
Сервер управляет составом, инстансом, сложностью, фазами боссов, смертью, восстановлением, наградами и лимитами. Учитывать реконнект, AFK, серверный матчмейкинг, масштабирование по группе и понятные телеграфы. Для рейдов 10 игроков отдельно определить взаимодействие двух групп без изменения обычного лимита группы 5. Инстансы не должны перегружать Android с 6 ГБ RAM.

## Godot-редактируемость
Проектные `.tscn`: DungeonEntrance, DungeonLevel3D, DungeonHud, DungeonResultsPanel, RaidBossArena, RaidRosterPanel; `.tres`: DungeonDefinition, DungeonDifficultyDefinition, RaidDefinition, DungeonRewardDefinition. Все локации, окружение, боссы, камеры, VFX, UI и анимации должны быть редактируемыми через Godot 4.7.2 на ПК; серверные правила и награды авторитетны.
