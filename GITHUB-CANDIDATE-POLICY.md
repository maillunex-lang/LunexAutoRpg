# Постоянное правило: GitHub-кандидаты на каждом этапе

**Владелец утвердил 23.11.2026. Применяется к каждому будущему этапу LunexAutoRpg, включая GDD, исследование, архитектуру, арт и разработку.**

1. До проектирования реализации каждого этапа обязательно искать на GitHub релевантные готовые решения, плагины, шаблоны, сценографические инструменты, фреймворки и примеры.
2. Анализировать несколько вариантов: функции, поддержка Godot 4.7.2, Android Compatibility, лицензия, поддержка upstream, качество, нагрузка, пригодность для сервер-авторитетной онлайн-игры, безопасность, стоимость внедрения и риск сломать существующий код.
3. Давать кандидату уникальный ID и рекомендацию **USE / ADAPT / STUDY / REJECT**, с основанием, ссылкой, требованиями к проверке и последствиями.
4. Если готовое решение действительно подходит, предлагать его **использовать или адаптировать**, а не писать всё с нуля автоматически.
5. Кандидата можно читать и проверять без интеграции. **Любая установка, копирование, адаптация, добавление зависимости или интеграция в основную игру только после отдельного явного утверждения владельца.**
6. Все утверждённые решения, результаты проверок и статусы кандидатов фиксировать в GitHub `main`, GDD и ROADMAP; для проектной памяти использовать @devbridgelunex `LunexAutoRpg`.
7. Сохранять концепцию собственного проекта и игровой ориентир Era of Celestials без копирования чужих авторских ассетов.
8. **Жёсткое ограничение:** GDD-08 не внедрять, пока 7.7.8 не принят вручную и не дано отдельное разрешение.

При отсутствии подходящего готового решения прямо указывать, почему целесообразна собственная реализация.
